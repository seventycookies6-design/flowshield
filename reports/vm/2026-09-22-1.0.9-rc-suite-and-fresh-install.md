### `flowshield://` (#294)

On `3bccbca` the link was never registered. Only Velopack's install hook
(`--veloapp-install`) registered it, and Velopack kills that hook after 30 s.
The first cold start under Defender took longer than that. This probably also
explains the note in [2026-09-18-1.0.7-fresh-install.md](2026-09-18-1.0.7-fresh-install.md)
that the key was missing straight after a silent install.

#295 has the installed copy check the registration on every start and repair it.
Re-check on `2899835`, with the key deleted to reproduce a killed hook:

- Launch → `FlowShield starting`, then `flowshield:// registered` 3.5 s later. The
  command is exactly `"…\FlowShield\current\FlowShield.exe" "%1"`.
- Opening `flowshield://activate?key=…` through the shell with the app running →
  `second launch handed over` → `activation link received; waiting for confirmation`.
  Still one process.
- With the terms gate still open, the gate stays on top. After accepting it, the
  activation prompt shows the link's key. Cancel dismissed it; Activate was never pressed.
- Uninstall still removes the key, and nothing re-registers it.

## Bench notes

- After every revert, turn off display sleep over PS Direct (`powercfg /change
  monitor-timeout-ac 0` and friends). While the guest's display is off, processes
  started into the desktop session freeze at start-up. That looked like hung
  tests for two hours.
- Start the app and helpers as interactive scheduled tasks. Launch Python with
  `pythonw.exe`: a console `python.exe` can hang in the Windows Terminal hand-off.
- Waking the display from the host with Shift eventually opens the Sticky Keys
  prompt (five presses), which takes the foreground. Wake with Ctrl instead.
- **To re-measure:** right after a revert, 1.0.8's first start took about 10 minutes
  to a usable window, with a busy UI thread and heavy paging on the 4 GB guest.
  The process started at 00:32, logged `FlowShield starting` at 00:35, and painted
  its window at about 00:42. The 1.0.9 RC's first start earlier that night took
  about 80 s. That points to the bench's memory, not a 1.0.8 bug, but a cheap
  4 GB laptop is a real customer. Worth timing again with more guest RAM.
