## 4. Uninstall and the Jump List file: record for Keenan's privacy decision

- **Before uninstalling**, FlowShield's `.customDestinations-ms` held the template names and `--start-sprint=<id>` arguments.
- **After `Update.exe --uninstall --silent`**, that file was gone. No file in `CustomDestinations` held `--start-sprint`, a template name or `Maths & Physics`, while other apps' files were untouched.
- So on this machine, Windows (or Velopack's uninstall) removed it along with the app. The "does it go when another app's Jump List is rebuilt" question didn't arise.
- Note: the names are stored as UTF-16 at odd byte offsets, so `Select-String -Encoding Unicode 'Light study'` can miss them in a file that does contain them. Search for `--start-sprint` too.

## Weak spots: not proven here

- **The pinned-taskbar right-click itself.** Pinning FlowShield and opening its taskbar menu are shell actions UI Automation can't drive reliably. This run proves that Windows stored the right four entries and that each entry's exact command does the right thing. It doesn't prove the entries appear in the pinned icon's menu without an explicit AppUserModelID, which #308 flagged as the risk. That needs about two minutes by hand in the VM: pin, then right-click.
- **How `Maths && Physics` renders** in the menu. It's stored the way the shell expects, but nobody looked at the menu.
- **The heads-up toast on screen.** The log shows the notification posted at 16:35:08. The screenshot was taken 4 s earlier, so it doesn't show it.
- **On-time start.** The sprint started 57 s after 16:40, although the planner ticks every 15 s. The probe also restored the window from the tray at 16:40:40, which may have played a part. Worth a look.
- **Not in this build:** #312 and #313. The Delete everything → Jump List cleanup (#313) wasn't tested.
- Quitting was done with a forced kill, not the tray's Quit; the missed-start rule only needs FlowShield not running at the start time.
