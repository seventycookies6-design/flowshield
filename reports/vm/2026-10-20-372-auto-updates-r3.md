## Problems

- **The actual blocker was G: write failure plus the guest fatal event, not the ordinary post-restore wait.** The fresh OFF restore became ready in 4m45s and its interactive probe passed. Testing stopped under the brief's explicit storage/crash rule. The OFF installer had started, but no causal link from app code to the storage incident is established. This single incident was not intentionally reproduced.
- **Cold startup was slow across unrelated guest programs.** The isolated Python marker eventually passed after roughly three minutes. The guest screenshot task also eventually completed. The initial 90-second app-window wait expired; a later command reached the existing app, accepted terms, and skipped first-run setup. Do not infer a product regression from those runner deadlines or use this shared-host VM as a load/performance benchmark.
- **The first install's Velopack fast hook timed out.** `cycle-a\velopack.log` records the `--veloapp-install` hook starting at guest 20:11:29, `Process timed out after 30s and was killed` at 20:12:00, and `Installation completed successfully!` at 20:12:01. Installed version, app launch, local-feed support, staging, and update were subsequently observed. The hook itself is not claimed to have passed; its timeout was not reproduced or classified as a product bug.
- **Expected VMMS event 20790 occurred on the two restores.** VHDX security-info access denied was retained in `events-Microsoft-Windows-Hyper-V-VMMS-Admin.json`. It did not prevent the first fresh restore from reaching PS Direct/interactive readiness and was not used as a blocker.
- **Runner corrections were bench errors.** Corrected a host ScriptBlock binding error, a nonexistent `win32process.ProcessIdToSessionId` diagnostic call, and reading a still-open Python log without FileShare.ReadWrite. The first stalled Python install runners were stopped before they launched an installer. The successful install used a separate interactive cmd task. None of these is counted as a product failure.
- **Readiness cleanup needed an outer deadline.** The first post-restore poller stalled after reporting an early remoting failure; only that poller was stopped, and `readiness-bounded.ps1` continued against the original 15-minute boot deadline. All completed attempts/errors are retained. Host wrapper `ExitCode` fields are null and are not used as proof of success; pass claims use recovered app/native-UI/version/settings evidence.
- **Evidence naming/collection details:** legacy `action-center.png` actually shows the native toast; the old `#n` shortcut did not establish Notification Center behavior. No Notification Center assertion is made. Repeated early collection nested a newer app log under `cycle-a\app-logs\logs\`; `cycle-a\app-log-final.log` is an exact copy of that newest raw file. Both original snapshots remain in the archive. The collector was corrected for later use.
- **Product bugs found: none established.** Checks 2/3/5 remain unknown. This run says nothing about signing, payments, other hardware, or performance under real load; the documented bench limits apply.
