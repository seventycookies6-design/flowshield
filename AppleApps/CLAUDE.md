# Apple apps — native SwiftUI (Mac now, iPhone later)

Read [the root CLAUDE.md](../CLAUDE.md) first. Basalt is the product name;
FlowShield remains the repository and `flowshield://` link name. Customer copy
uses American **license**. The Mac app is a beta (#426, tracking #425): it is not
offered to customers until it can be signed and notarised, which needs the paid
Apple Developer Program (#166). The iPhone app (#424) waits for the same
membership. Never add a site claim, download link or purchase path for either.

## Layout

- `project.yml` — the XcodeGen spec. The generated `Basalt.xcodeproj` is not
  committed; run `xcodegen generate` after pulling.
- `BasaltCore/` — a Swift package of pure logic (Foundation only, no AppKit or
  SwiftUI), ported from Windows and shared with the future iPhone app. The Mac
  matches Windows, not Android, where the two differ.
- `Basalt/` — the Mac app: `AppModel` (state and intents), the blocker, system
  integration and the SwiftUI views. `Tokens.xcassets` is generated by
  `tools/build_tokens.py`; never edit it by hand.
- `BasaltTests/` — app-layer unit tests. `scripts/e2e_blocker.sh` proves the
  blocker on a real Mac.

## Build and test

You need a Mac with Xcode 26 or later and XcodeGen (`brew install xcodegen`).
Keep the code compatible with the Xcode 26 SDK that CI uses: no APIs newer than
macOS 26. On a Mac, from `AppleApps/`:

```bash
swift test --package-path BasaltCore
xcodegen generate
xcodebuild -project Basalt.xcodeproj -scheme Basalt -configuration Debug build
```

From Windows (or any other checkout), `tools/mac_remote.sh` copies `AppleApps/`
to the team Mac over SSH and runs the same steps there: `test`, `build`, `run`,
`ssh <command>`. It needs an SSH host entry, `devmac` by default
(`BASALT_MAC_HOST` overrides it). Each branch gets its own folder on the Mac
(`BASALT_MAC_DIR` overrides it), so parallel work doesn't collide. Over SSH the
Mac's login keychain is locked and screen capture is blocked, so tests use
neither; `open` still launches the app into the logged-in session, so the
blocker really runs.

The blocker's end-to-end proof, on the Mac after a build:

```bash
tools/mac_remote.sh ssh "bash scripts/e2e_blocker.sh \$HOME/basalt-remote/<branch>/DerivedData/Build/Products/Debug/Basalt.app"
```

It uses a throwaway data folder, takes a lock so two runs can't overlap, and
quits Calculator and Basalt when done. Don't run it while someone is using the
Mac's screen.

## Debug-only test hooks

Compiled out of Release builds:

- `--data-dir <path>` — a separate data folder. Every test uses one; nothing
  automated may touch `~/Library/Application Support/Basalt`.
- `--skip-onboarding` — accept the terms and skip first run, in that folder only.
- `--test-timings` — the shortened waits Windows' `--short-timers` has.
- `--start-sprint shield=<soft|firm|sealed> minutes=<n> block=<bundle id>[,…]`.
- `--snapshot-dir <path>` — render every screen to PNGs in light and dark, then
  quit. This is how design is reviewed without screen capture.
- `blocker.log` in the data folder records every blocker decision.

## The deliberately timid blocker on macOS

Public AppKit only: `NSWorkspace` running applications, polled every 2 s and on
launch or activation. Soft shows a notice and closes nothing unless the person
chooses Close. Firm and Sealed ask the app to quit (`terminate()`, so it can
offer to save work), then `forceTerminate()` after the 10-second grace period.
Sealed also locks the blocklist. The pure decisions live in
`BasaltCore/MacBlockerPolicy.swift` with tests.

Never close Basalt, Finder, the Dock, loginwindow, WindowServer, SystemUIServer,
Control Centre, Notification Centre, Spotlight, System Settings, Activity
Monitor, terminals, editors or developer tools, and never an Apple process
unless it is a user-facing app the person listed by bundle id. Apple apps need
an explicit bundle-id entry; process-name matching never reaches them.

Never add admin rights, a privileged helper, kernel, system or network
extensions, hosts-file or packet-filter edits, uninstall protection, or a
requirement for Accessibility or Screen Recording permission. App Sandbox stays
off only because closing other apps needs it off; that is also why the Mac app
ships outside the Mac App Store. Apple's Screen Time API isn't available to Mac
apps.

## Design

Follow `DESIGN_SYSTEM.md`: Part A's Apple-platforms rule (Apple's Human
Interface Guidelines first, Basalt's colour meaning, calm, shield language and
word list on top) and Part B §12a. Settings is a Settings window, not a sidebar
page. Liquid Glass comes from system components only, never on content. Copy
stays verbatim from Windows except platform words: menu bar for tray, Mac for
PC, Open at login for Start with Windows. Give controls accessibility labels and
`.accessibilityIdentifier`s that reuse the Windows `AutomationId` names where a
control maps.

## Data and privacy

Settings and history are schema-versioned JSON in
`~/Library/Application Support/Basalt/` with file mode 0600. The licence check
sends exactly what Windows sends (`licenseKey`, `email`, `deviceId`,
`deviceName`); tier 5's `test_apple_app.py` holds that, and anything new that
leaves the Mac goes into the privacy policy in the same pull request. Before the
Mac app reaches customers, the privacy policy must also describe Mac storage:
it currently describes Windows' DPAPI encryption.
